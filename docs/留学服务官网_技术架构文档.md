## 1. 文档目的与原则

### 1.1 目的

给出可落地的技术架构：系统边界、逻辑/物理视图、数据模型、接口、安全合规、可观测性，以及 **P0 / P1 / P2** 演进路径。业务「为什么」见业务架构；功能细则见 PRD。

### 1.2 架构原则

| 原则 | 含义 |
|---|---|
| SEO/AEO First | 核心页 SSR/SSG，正文对爬虫可见 |
| 简单可运营 | MVP 单体或「前端 + 轻量 API + CMS」，不先上微服务丛林 |
| 线索不失 | 入库优先于通知；通知失败可重试 |
| 隐私默认 | 最小采集、同意审计、权限分离 |
| 飞轮可观测 | 下一站、答案块、UTM 等事件可分析 |
| 可替换集成 | 邮件/企微/统计用适配层，避免锁死 |

### 1.3 质量属性优先级（MVP）

1. 正确性与线索可靠性  
2. 移动性能与可抓取性  
3. 安全与隐私  
4. 可维护性  
5. 弹性扩展（P2 再强化）

## 3. 推荐技术选型（默认栈）

初创优先「一人可维护、国内访问友好、SSR 强」。下列为**默认推荐**，评审时可替换，但需满足第 1.2 原则。

| 层级 | 默认选型 | 备选 | 说明 |
|---|---|---|---|
| 前台框架 | Next.js（App Router）+ TypeScript | Nuxt 3 | SSG/SSR、Metadata、Sitemap 成熟 |
| 样式 | CSS Modules 或 Tailwind（定制设计令牌） | — | 避免模板化默认皮肤；品牌字体自托管 |
| 内容 | Headless CMS（Sanity / Strapi / 国内可自托管 Directus） | MDX + Git | 编辑要友好则 Headless；极简可用 MDX |
| API | Next.js Route Handlers 或轻量 Nest/Fastify | — | MVP 可同仓 |
| 数据库 | PostgreSQL | MySQL | 线索与账号强一致 |
| 缓存/会话 | Redis（P1） | — | 限流、会话 |
| 文件 | 对象存储（S3 兼容 / 阿里云 OSS） | — | 图片、微信码、案例图 |
| 部署 | 容器 + 云主机，或 Vercel + 国内源站/CDN 折中 | 阿里云 SAE | **国内用户**需评估延迟与备案 |
| 分析 | GA4 和/或 百度统计 | Plausible | 事件命名统一 |
| 邮件 | 企业邮 SMTP / SendGrid / 阿里邮件推送 | — | 线索通知 |
| 鉴权（后台） | 邮箱密码 + session；P1 MFA | Clerk/Auth.js | 后台独立 |

### 3.1 国内备案与托管决策点

| 方案 | 优点 | 风险 |
|---|---|---|
| 全站国内云 + ICP | 百度友好、延迟低 | 需备案周期 |
| 海外边缘 + 国内用户 | 上线快 | 国内慢、百度抓取不稳 |
| **推荐** | 生产目标：**国内备案域名 + 国内源站/CDN**；开发可用海外预览环境 | 与业务获客一致 |

| 域 | 职责 | MVP 形态 |

## 5. 物理 / 部署架构

### 5.1 MVP 部署拓扑

```
用户/爬虫
   │
   ▼
[DNS] → [CDN（静态资源+缓存 HTML 可配置）]
   │
   ▼
[WAF/防火墙 可选]
   │
   ▼
[应用节点 ×1～2]  Next.js（Web+API+Admin）
   │
   ├── PostgreSQL（托管）
   ├── OSS
   └── 日志（云日志服务）
```

单区域即可；可用性目标 MVP：**月度 99.5%**（非金融级）。

### 5.2 环境

| 环境 | 用途 |
|---|---|
| local | 开发 |
| staging | 预发、内容预览、表单打到测试邮箱 |
| production | 正式 |

密钥：环境变量 / 云密钥管理，禁止入库。

### 5.3 CI/CD（最小）

```
git push → lint + typecheck + build → 部署 staging
         → 人工确认 → 部署 production
```

内容发布走 CMS，不强制每次发版；配置类（电话、微信图）走后台设置热更新。

## 6. 前台信息与渲染架构

### 6.1 路由与渲染策略

| 路由类型 | 策略 | 原因 |
|---|---|---|
| 首页、服务、垂直、关于、合规 | SSG + 按需再生成（ISR） | SEO、性能 |
| 指南、案例详情 | SSG/ISR | 大量长尾 |
| 预约页 | SSR 或 CSR+强校验 | 表单新鲜度 |
| 感谢页 | SSR/SSG + **noindex** | 防收索引 |
| 后台 Admin | CSR，独立鉴权，**禁止索引** | 安全 |

### 6.2 SEO / AEO 技术组件

| 组件 | 实现要点 |
|---|---|
| Metadata | 每页 title/description/canonical |
| JSON-LD | FAQPage、Article、Breadcrumb、Organization |
| sitemap.xml | 构建或运行时生成；含 lastmod |
| robots.txt | 放行资产；Disallow /admin /api 私有 |
| llms.txt | `public/llms.txt` 静态，发版或后台可改 |
| 答案块 | 独立 DOM + 稳定锚点 `#answer` |
| 可见日期 | `dateModified` 字段渲染 |

### 6.3 飞轮前端组件（与 PRD 对齐）

```
<AnswerBlock />
<ReadingProgress />
<NextStops items={[...]} />          // 触发 next_content_click
<ClaritySummary points={[...]} />
<CaseLikeMe filters=... />
<LeadForm variant="short|book" />
<StickyMobileDock />                 // 评估|微信|电话
```

P1：`ChecklistTool`、`MatchQuiz`、`ContinueLast`（localStorage）。

### 6.4 相关推荐算法（P0）

规则引擎，无需 ML：

1. 同 `track` 或同 `country`  
2. 同 `intent` 标签（费用/条件/时间）  
3. 同学位层级  
4. 人工置顶覆盖  

输出 2–4 条；不足则回落「热门垂直」。

## 9. API 架构

### 9.1 公共 API（访客）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/leads` | 创建线索；校验、限流、写库、扔 outbox |
| GET | `/api/health` | 探活 |

P1：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/tools/continue` | 可仅前端本地，无 API |
| POST | `/api/tools/match` | 测验结果（可无登录） |
| GET | `/r/:code` | 短链 302 + 计次 |

### 9.2 `POST /api/leads` 合同（摘要）

**请求**

```json
{
  "name": "张先生",
  "mobile": "13800000000",
  "track": "uk-pg",
  "formVariant": "short",
  "sourceUrl": "https://example.com/guides/...",
  "landingSlug": "uk-pg",
  "utm": { "source": "douyin", "medium": "social", "campaign": "uk-pg-fee-2026" },
  "preferredAdvisorId": null,
  "consent": true,
  "privacyVersion": "2026-09-28",
  "website": ""  
}
```

`website` 为蜜罐字段，有值则静默丢弃或 204。

**响应** `201 { "ok": true, "leadId": "..." }`  
失败：`400` 字段错误；`429` 限流。

### 9.3 后台 API

REST 资源：`/api/admin/articles|cases|advisors|leads|settings`  
鉴权：Session Cookie，`SameSite=Lax`，CSRF 双提交或同源强制。

### 9.4 幂等与限流

- 同一 `mobile + landingSlug` 10 分钟内重复提交：更新备注/计数，不重复狂发邮件（可聚合）。  
- IP 限流：如 10 次 / 10 分钟（Redis P1；MVP 可用内存+边缘限流）。

## 10. 集成架构

```
LeadAPI ─写入─► PostgreSQL
   │
   └─outbox─► Worker/Cron ─┬─► SMTP 邮件
                           └─► 企微 Webhook（P1）
```

| 集成 | MVP | 失败策略 |
|---|---|---|
| 邮件通知 | 有 | 入库成功即 201；邮件重试 3 次 |
| 企微 | P1 | 同上 |
| GA4/百度 | 前端 SDK | SDK 失败不影响表单 |
| OSS | 有 | 上传失败阻发布 |
| 百度/谷歌站长 | 运营人工 | 非运行时依赖 |

适配层接口示例：`NotificationPort.sendLeadCreated(lead)`。

## 11. 安全架构

### 11.1 威胁与控制

| 威胁 | 控制 |
|---|---|
| 撞库/刷表单 | 限流、蜜罐、手机号格式校验 |
| XSS | 反应框架默认转义；CMS 富文本消毒 |
| CSRF | 后台 Cookie + CSRF；公共 POST 无 Cookie 依赖 |
| 后台爆破 | 强密码、失败锁定、P1 MFA |
| 数据泄露 | RBAC、脱敏、导出审计、库网隔离 |
| 供应链 | 锁版本、CI 审计依赖 |

### 11.2 隐私（个保法对齐）

- 提交前同意；存 `consent_at` + `privacy_version`  
- 删除权：工单流程 P0 人工；P1 后台「匿名化」按钮  
- 日志禁止打印完整手机号  

### 11.3 密钥

| 密钥 | 存放 |
|---|---|
| DB、SMTP、OSS | 云密钥 / env |
| CMS Token | 仅服务端 |

| 事件 | 属性 |
|---|---|
| cta_click | location, page |
| form_start / form_submit_success / fail | variant, track |
| wechat_click / phone_click | page |
| next_content_click | from, to |
| answer_block_view | page |
| case_view / case_filter | id, filters |
| checklist_tick / quiz_complete | P1 |

UTM 在落地时写入 `sessionStorage` 并随表单提交，防路径跳转丢失。

### 12.3 SEO 运维

- Search Console / 百度站长：索引覆盖周检  
- 死链与 404 比率  
- Core Web Vitals 抽样

## 14. 演进路线（技术）

### 14.1 P0（MVP）

- Next 单体：访客站 + Admin + Lead API  
- PostgreSQL + OSS + SMTP + 基础埋点  
- SSG/ISR 内容页、Schema、sitemap、llms.txt  
- Outbox 邮件通知  
- 发布校验闸门  

### 14.2 P1

- Redis 限流  
- 企微通知、短链服务  
- Match/Checklist  
- 仪表盘聚合（可 SQL 视图 + 简单图表）  
- MFA、导出审计  
- 媒体库、301 管理  

### 14.3 P2

- 内容原子库与发布日历  
- 个性化推荐（仍可规则+简单协同）  
- 学员门户域拆分  
- 若流量增大：读写分离、队列中间件、Admin 独立部署  

### 14.4 明确不引入（除非指标倒逼）

- Kubernetes 大集群（单机/双机足够时）  
- 中心化 ES 搜索（内容量小用 DB + 标签）  
- 自研推荐模型
