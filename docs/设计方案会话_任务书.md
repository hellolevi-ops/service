## 2. 风格方案：必须出「多套完整方案」

至少设计 **3 套互不雷同** 的完整视觉方向（不是换个主色那么简单），每套都要能支撑：首页、垂直落地页、案例、顾问、Lab、社区轻量皮肤。

**建议命题（可调整命名，但覆盖这三个张力）：**

| 方案代号 | 方向意图 | 对中国区的假设 |
|---|---|---|
| A「书院研判」 | 克制、纸感、编辑型排版、信任优先 | 家长向：稳、专业、少促销 |
| B「赛道工作室」 | 当代品牌、强第一屏、垂直专家感 | 学生向：清晰有锋芒，仍忌土促销 |
| C「工具实验室」 | Lab/工具感、信息密度、模块化 | 强调方法论与自助，顾问作升级路径 |

**硬性避让（来自既有设计规则 + 中国区原则）：**

- 禁止默认 AI 三套娃：紫白渐变、奶油衬线+陶土、报纸细线密栏  
- 禁止第一屏仪表盘化、统计条堆砌、英雄区卡片拼贴  
- 品牌名必须是第一屏主信号  
- 默认少卡片；卡片仅用于可交互列表项  
- 微信/电话/评估通道在移动端始终可及，但不破坏第一屏品牌构图  

每套方案必须写清：**适合什么客单价/什么垂直**；最终在总纲里推荐 **1 套主风格 + 可选季节皮肤策略**。

## 3. 业务 / 技术 / 组件设计要点（防 low）

### 3.1 业务设计

- 用调研「六层专业结构」检查方案是否齐全：国家×学历×产品、案例、顾问、生命周期、转化、工具、内容。  
- 写清 **SKU 与垂直包装** 关系（垂直是获客包装还是独立产品）。  
- 线索状态机、SLA、顾问分配与 PRD/业务架构 v2 一致并补设计层细节（话术边界、家长同步节奏）。  
- Lab 与社区：**业务上如何服务信任与飞轮，而不抢服务骨架的戏**。

### 3.2 技术设计

- 承认 HK 现状：`/data/studyabroad`、Next、PG、Redis、Directus、本地 uploads。  
- 给出内容模型（Directus collections）草案：Article、Case、Advisor、Track、Faq、LabTool、CommunityPost…  
- Lead API、同意审计、UTM、outbox 通知保留并细化。  
- 社区登录墙 / 防爬与 SEO 隔离的技术策略写清楚。  
- P0 不引入过重中台；但文档深度要对齐「专业系统」而非「单页站」。

### 3.3 组件设计

- 分层：Foundation（色/字/间距）→ Primitives → Patterns → Domain（留学业务组件）。  
- 每个 Domain 组件写：**对应 PRD 用户故事或能力域编号**。  
- 转化组件必须含：渐进式表单字段、蜜罐、隐私勾选、成功态（加企微）。
