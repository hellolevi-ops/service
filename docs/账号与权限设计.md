## 1. 为什么两套账号

| 体系 | 用途 | 入口 |
|---|---|---|
| 客户 `customer` | 社区 L1、个人中心、收藏、L2 认证 | 顶栏「登录」、`/login`、`/account` |
| 员工 `staff` | 线索工作台、在读认证审核；内容仍走 Directus | `/ops/login`（公网不链） |

硬约束：客户不可进 `/ops` 与 Directus；员工不可当社区马甲；留资不强制先注册。

## 2. 客户

- **登录方式**：手机号 + 短信验证码；首次验证成功即建号。
- **分层**：L0 访客 → L1 登录 → L2 在读认证（`/account` 申请，`/ops/verifications` 审核）。
- **Cookie**：`sa_session`（HttpOnly, SameSite=Lax）。
- **开发**：`AUTH_DEV_OTP=1` 时验证码固定为 `888888`。
- **Phase B**：资料编辑、关联线索、收藏（案例/指南）、L2 工单；微信绑定待开放平台凭证。

## 3. 员工

| 角色 | Ops 线索 | 在读认证审核 | 明文手机号 | Directus |
|---|---|---|---|---|
| admin | 全部 | 是 | 可揭示/导出 | Admin |
| editor | 只读或无 | 否 | 否 | 内容编辑 |
| advisor | 默认可全部 | 是 | 需勾选揭示 | 无写权限 |

- **登录**：邮箱 + 密码 → Cookie `ops_session`。
- **Break-glass**：`OPS_ADMIN_KEY` / `REVALIDATE_SECRET`。
- **入口**：`/ops/leads`、`/ops/verifications`。

## 4. 数据表

- `users` / `otp_challenges` / `sessions` / `user_lead_links`
- `user_favorites` / `verification_requests`
- `staff_users` / `staff_sessions`

## 5. API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/otp/send` | 发验证码 |
| POST | `/api/auth/otp/verify` | 校验并建会话 |
| GET/PATCH | `/api/auth/me` | 读/改资料 |
| GET | `/api/auth/leads` | 我的线索（脱敏） |
| GET/POST/DELETE | `/api/auth/favorites` | 收藏 |
| GET/POST | `/api/auth/verification` | L2 申请 |
| GET/PATCH | `/api/ops/verifications` | 员工审核 |
| POST | `/api/ops/auth/login` | 员工登录 |

## 6. 分期

- **A**：OTP 登录、顶栏入口、社区真会话、Ops 员工登录。
- **B（本轮）**：个人中心完善、收藏、L2 认证工单；微信绑定占位。
- **C**：社区发帖审核队列、家长区、SLA 看板、正式短信/微信 OAuth。
